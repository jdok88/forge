# Forge Master 알람 앱 — 설계 문서

작성일: 2026-08-14

## 1. 목적

모바일 게임 Forge Master의 장시간 타이머(펫 부화 / 기술 테크트리 / 대장간)를
서버·계정별로 관리하고, 완료 시점에 **앱이 닫혀 있어도** 푸시 알림을 받는다.
부가로 자원 수급률을 입력하면 다음 단계 착수 가능 시점을 예측한다.

주 사용 환경은 **모바일**(안드로이드·iOS). 링크로 배포되는 PWA.

## 2. 스코프

### 포함

- 서버 다중 등록, 서버별 계정 다중 등록, 계정 구분 표기
- 타이머 3종 알림: 펫 부화(슬롯 4), 기술 테크트리(1), 대장간(1)
- 일일퀘스트 체크리스트 + KST 09:00 리셋 전 미완료 알림
- 계정별 단축/할인 노드 레벨 입력 → 소요시간·비용 자동 보정
- 계정별 수급률 입력 → 다음 착수 가능 시각 예측
- 젬 즉시완료 비용 표시

### 제외

- 스킬/마운트 소환 확률, 대장간 재질 확률표
- 파워 트리 스탯 계산기
- 게임 계정 연동(공식 API 없음). 모든 상태는 사용자 수동 입력

## 3. 게임 데이터 (검증 완료)

출처: `image/` 디렉터리의 커뮤니티 시트(discord.gg/forgemaster) 및 Tech Tree Guide.
모든 값은 표 간 교차 검증 및 공식 역산으로 확인했다.

### 3.1 공통 공식

```
소요시간 = 기본시간(초) / (1 + 속도%/100)      # forgedatarealreal 각주에 명시
비용     = 기본비용 × (1 - 할인%/100)          # 30→15 (-50%), 400→300 (-25%)
젬       = ceil(남은시간(초) / 434.8)          # 대장간·테크 전 구간 동일 환율
```

시간은 **나눗셈**, 비용은 **곱셈**이다. 혼동 주의.

### 3.2 단축/할인 노드

각 노드는 티어 I~V × 서브레벨 5 = **25단계**. 효과는 서브레벨당 가산.

| 대상 | 서브레벨당 | 25단계 최대 |
|---|---|---|
| 펫 부화 속도 (등급별 6개 노드 독립) | +10%p | +250% |
| 테크 연구 속도 | +4%p | +100% |
| 테크 물약 비용 | -2%p | -50% |
| 대장간 시간 | +2%p | +50% |
| 대장간 골드 비용 | -1%p | -25% |

> Tech Tree Guide 본문의 대장간 수치(4%/2%)는 **틀렸다**. `forgedetail-1`(2%씩 50% 상한),
> `forgedetail-5`(1%씩 25% 상한)가 정본.

## 4. 아키텍처

```
[모바일 브라우저]
  PWA (React SPA)  ──REST/Realtime──▶  [Supabase]
   ├ Service Worker                      ├ Postgres (RLS)
   │   └ push 수신 → Notification        ├ Auth (매직링크)
   └ 로컬 카운트다운                      ├ pg_cron (1분/일 1회)
                                         └ Edge Function: dispatch-push
                                                └── Web Push (VAPID) ──▶ SW
```

- **프론트**: Vite + React + TypeScript, `vite-plugin-pwa`. Cloudflare Pages 정적 배포
- **백엔드**: Supabase 무료 티어
- **인증**: 매직링크(이메일). 기기 교체·다기기 동시 알림 지원
- **푸시**: VAPID Web Push. 구독은 기기당 1건, 한 사용자가 여러 기기 등록 가능

### 왜 서버가 필요한가

앱이 닫힌 상태의 알림은 브라우저가 서버 푸시를 받아야만 발생한다.
Service Worker의 `setTimeout`은 브라우저가 SW를 수시로 종료시키므로 신뢰할 수 없다.
따라서 만기 판정과 발송은 전적으로 서버가 담당한다.

### iOS 제약 (필수 안내)

iOS는 **Safari로 접속 → 공유 → 홈 화면에 추가**를 거쳐야만 푸시를 받는다(iOS 16.4+).
링크 클릭만으로는 불가하며 우회 방법이 없다. 최초 진입 시 설치 안내 화면을 노출한다.

## 5. 데이터 모델

게임 상수(3장 표)는 **DB가 아닌 프론트 코드에 하드코딩**한다. 버전 관리가 쉽고 오프라인에서도 계산된다.

```sql
servers (
  id uuid pk, user_id uuid fk→auth.users,
  name text, sort_order int, created_at timestamptz
)

accounts (
  id uuid pk, user_id uuid fk, server_id uuid fk→servers on delete cascade,
  nickname text, color text,              -- 구분 표기용
  forge_level int default 1,              -- 1..35, 완료 시 자동 +1
  forge_speed_lv int default 0,           -- 0..25
  forge_cost_lv int default 0,
  tech_speed_lv int default 0,
  tech_cost_lv int default 0,
  egg_speed_lv jsonb default              -- 등급별 0..25
    '{"common":0,"rare":0,"epic":0,"legendary":0,"ultimate":0,"mythic":0}',
  gold_per_min numeric,                   -- nullable, 예측 기능용
  hammer_per_min numeric,
  potion_per_day numeric,
  sort_order int, created_at timestamptz
)

timers (
  id uuid pk, user_id uuid fk,
  account_id uuid fk→accounts on delete cascade,
  kind text check (kind in ('egg','tech','forge')),
  slot int,                               -- egg: 1..4 / tech·forge: 1
  meta jsonb,                             -- egg:{rarity} tech:{nodeId,tier,level} forge:{targetLevel}
  started_at timestamptz, ends_at timestamptz,
  notified_at timestamptz,                -- 발송 완료 표시(중복 방지)
  completed_at timestamptz                -- 사용자 확인 시각
)
-- 활성 타이머 중복 방지
create unique index on timers (account_id, kind, slot) where completed_at is null;

daily_quests (
  user_id uuid fk, account_id uuid fk, quest_date date, quest_key text,
  done_count int default 0,
  primary key (account_id, quest_date, quest_key)
)

push_subscriptions (
  id uuid pk, user_id uuid fk,
  endpoint text unique, p256dh text, auth text,
  user_agent text, created_at timestamptz, last_ok_at timestamptz
)

notification_prefs (
  user_id uuid pk,
  daily_quest_remind_hours_before int default 2,   -- 리셋 N시간 전
  daily_quest_enabled bool default true
)
```

모든 테이블에 RLS: `user_id = auth.uid()`.

`quest_date`는 **KST 기준 날짜**로 저장한다(리셋이 09:00 KST이므로,
KST 09:00 이전은 전날 날짜로 취급).

## 6. 계산 모듈

순수 TypeScript 함수로 분리(`src/game/`). DB·React 의존 없음 → 단위 테스트 용이.

```ts

applySpeed(baseSec: number, speedPct: number): number     // baseSec / (1 + p/100)
applyDiscount(baseCost: number, discPct: number): number  // baseCost * (1 - p/100)

// durations.ts — 계정 설정을 받아 실제 소요시간/비용 산출

resourceEta(need: number, have: number, perMin: number): number | null  // 분, 불가시 null
```

## 7. 화면

### 7.1 홈

- 서버별 섹션 → 계정 카드 목록
- 카드: 계정명(색상 뱃지), 진행 중 타이머 요약(예: `🥚2 ⚗️1 ⚒️1`), 가장 빠른 완료까지 남은 시간
- 일퀘 미완료가 있으면 뱃지
- 하단: 계정 추가 / 설정

### 7.2 계정 상세

- **펫 슬롯 4개** — 비었으면 등급 선택 → 시작. 진행 중이면 카운트다운 + 젬 즉시완료 비용 + 취소
- **테크 1칸** — 노드 선택 → 티어/레벨 선택 → 소요시간·물약 미리보기 → 시작
- **대장간 1칸** — 현재 레벨 표시, 다음 레벨 소요시간·골드 미리보기 → 시작. 완료 확인 시 레벨 +1
- **일퀘 체크리스트** — 5종, 탭할 때마다 카운트 증가, 리셋까지 남은 시간 표시
- **예측 패널** — 수급률이 입력된 항목만: "다음 대장간 골드까지 2d 7h", "다음 테크 물약까지 14h"

### 7.3 계정 설정

- 계정명·색상·서버
- 단축 레벨 10개 (0~25 스텝퍼): 대장간 속도/비용, 테크 속도/비용, 알 6등급
- 수급률 3개 (선택 입력)
- 각 항목에 현재 효과 표시(예: `+38% → 대장간 시간 27.5% 감소`)

### 7.4 설치 안내

최초 진입 또는 푸시 권한 미허용 시. iOS/안드로이드 분기하여 스크린샷 포함 안내.

### 7.5 테마 — 토큰 우선, 스킨은 후속

게임과 유사한 비주얼 컨셉은 **v1 이후 별도 패스**로 진행한다.
대신 v1부터 모든 색·간격·모서리·타이포를 CSS 커스텀 프로퍼티 한 파일
(`src/styles/tokens.css`)에 모으고, 컴포넌트는 리터럴 값을 쓰지 않는다.
이렇게 하면 스킨 작업이 토큰 교체로 끝난다.

v1 기본값은 다크 테마. 단, 아래는 게임 기준이 명확하므로 지금 토큰에 넣는다.

| 등급 | 토큰 |
|---|---|
| Common | `--rarity-common` (회색) |
| Rare | `--rarity-rare` (파랑) |
| Epic | `--rarity-epic` (초록) |
| Legendary | `--rarity-legendary` (노랑) |
| Ultimate | `--rarity-ultimate` (빨강) |
| Mythic | `--rarity-mythic` (보라) |

> 한계: 텍스처 패널·장식 프레임·비트맵 폰트 같은 무거운 스킨은 토큰 교체만으로
> 적용되지 않으며 마크업 변경을 수반한다. 그런 방향을 원할 경우 스킨 패스 착수 전에
> 게임 스크린샷을 확보해 컴포넌트 구조를 함께 재검토한다.

## 8. 알림 로직

### 8.1 타이머 만기

```
pg_cron: 매 1분
  → Edge Function dispatch-push
      SELECT * FROM timers
      WHERE ends_at <= now() AND notified_at IS NULL AND completed_at IS NULL
      → 사용자의 모든 push_subscriptions 로 발송
      → notified_at = now()
```

지연은 최대 60초. 게임 타이머 특성상 허용 범위로 판단한다.
발송 실패(410 Gone)면 해당 구독을 삭제한다.

알림 본문 예: `[루나서버 / 홍길동] 신화 알 부화 완료`
클릭 시 해당 계정 상세로 딥링크.

### 8.2 일일퀘스트

```
pg_cron: 매일 07:00 KST (리셋 2시간 전, prefs로 조정)
  → 미완료 퀘스트가 있는 계정을 사용자별로 묶어 1건 발송
```

예: `일퀘 리셋 2시간 전 — 3개 계정에 미완료 6건`

### 8.3 포그라운드 보정

앱이 열려 있을 때는 `ends_at` 기준 로컬 카운트다운을 표시하고,
만기 시점에 클라이언트에서 즉시 알림을 띄운다(서버 푸시보다 빠름).
중복은 SW에서 `tag`로 병합한다.

## 9. 에러 처리

| 상황 | 처리 |
|---|---|
| 푸시 권한 거부 | 배너로 안내, 포그라운드 타이머는 정상 동작 |
| iOS 미설치 상태 접속 | 설치 안내 화면 |
| 오프라인 | `ends_at`이 절대시각이므로 카운트다운은 정상. 쓰기는 큐잉 없이 실패 토스트 |
| 구독 만료(410) | 서버가 구독 삭제, 다음 접속 시 재등록 |
| 동일 슬롯 중복 시작 | DB 유니크 인덱스로 차단, UI에서도 비활성화 |
| 감축 레벨 범위 밖 입력 | 0~25로 클램프 |

## 10. 테스트

- **단위**: `src/game/` 순수 함수 — 6장 픽스처 전부 + 경계값(레벨 0, 25, 대장간 1·35)
- **통합**: Supabase 로컬 인스턴스에서 타이머 생성 → cron 함수 호출 → `notified_at` 갱신 확인
- **수동**: 실기기(안드로이드 Chrome, iOS 홈화면 PWA)에서 앱 종료 후 푸시 수신 확인

푸시 실기기 검증은 자동화가 어려우므로 체크리스트로 관리한다.

## 11. 향후 (v1 제외)

- 게임 컨셉 스킨 패스(토큰 교체 + 필요 시 컴포넌트 구조 조정) — 7.5 참조
- 오프라인 보상 시간 안내
- 스킬 소환 티켓 예측(유령마을 수급 연동)
- 계정별 커스텀 단축 설정의 유료화 분리
- 테크 노드별 진행도 전체 추적(현재는 진행 중 1건만)

## 12. 미해결 / 가정

- 테크 노드 47개의 **정확한 한글 명칭**은 가이드 영문 기준으로 임시 번역한다. 실제 게임 표기와 다를 수 있어 v1 이후 수정 가능하도록 상수 파일로 분리.
- 테크 표의 티어 간 시간 증가율이 II-5/5부터 ×1.1로 바뀌는 이유는 불명이나, 표시값을 그대로 사용하므로 영향 없음.
- 수급률(분당 골드·망치, 일일 물약)은 사용자가 직접 측정해 입력한다. 게임 내 자동 취득 수단 없음.
